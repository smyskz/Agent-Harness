# 古いAI報告書を締切日で判定して日付別に整理する

`reports/AI/`直下にある古い報告書を、日単位の締切で判定し、締切日の年、月、日を
階層化した`reports/AI/<YYYY>/<MM>/<DD>/`へ移動する。すでに日付別directory内に
ある報告書は対象外とする。

## 入力

- 任意の締切日: `YYYY-MM-DD`
- 省略時: 実行日

締切日以前の報告書を候補にする。締切日と同じ日付の報告書も移動対象に含める。
たとえば締切日が`2026-08-03`なら、`2026-08-03`以前を候補にし、
`2026-08-04`以後は対象外とする。

入力された締切日が実在する暦日でない場合や、`YYYY-MM-DD`形式でない場合は、
移動せずに入力の訂正を求める。

## 日付の決定

1. 各Markdownの冒頭を読み、報告全体の基準日を示す`調査基準日`、`調査日`、
   `比較基準日`、`作成日`、または同等の明示的な日付を使う。
2. 更新日と基準日が併記されている場合は、内容全体が更新済みだと明記されている
   ときだけ更新日を使う。それ以外は元の基準日を使う。
3. filesystemの更新時刻やGit commit日だけから報告日を推測しない。
4. 日付がない、複数の日付から基準日を一意に決められない、または日付と内容が
   矛盾する報告書は移動せず、確認事項として報告する。

## 実行手順

1. repository root、現在branch、`git status --short`、適用される指示を確認する。
2. `reports/AI/`直下のMarkdownだけを列挙し、報告日、締切日との比較、移動先、
   Git管理状態を表にする。
3. Markdownから直接参照される同名または付随するSVG、画像、data fileを特定し、
   報告書と同じdirectoryへ一緒に移動する単位として扱う。共有assetは自動移動しない。
4. 移動予定、除外理由、曖昧な項目、path衝突を変更前に提示する。候補がない場合は
   ファイルを変更せず終了する。移動先に同名pathがある場合は上書きせず停止する。
5. 利用者が移動内容を承認した後、締切日の年、月、日を使った
   `reports/AI/<YYYY>/<MM>/<DD>/`を作成する。
   Git管理対象は履歴を追跡できる方法で移動する。未追跡ファイルは、明示的に
   対象へ含める承認がない限り移動しない。
6. `README.md`、`reports/AI/`、`memory/`、その他のGit管理対象文書から旧pathへの
   参照を検索し、新pathへ更新する。Markdownの相対linkは参照元から再計算する。
   外部URL、固定commitへのURL、引用内のpathは意味を確認せず機械的に変更しない。
7. 移動したMarkdown内の相対linkとasset参照を検証し、READMEの報告書索引が
   実在する新pathを指すことを確認する。旧pathへの未更新参照も再検索する。
8. `git diff --check`と`git status --short`を確認し、移動前後の対応、更新した参照、
   除外項目、検証結果を報告する。

## 制約

- 報告書の本文、日付、結論を、移動のためだけに書き換えない。
- 利用者の未コミット変更を破棄、stash、上書き、stage解除しない。
- `reports/AI/`以外の成果物を、付随assetまたは参照更新という理由だけで移動しない。
- report同士のlink、README索引、memoryのevidence pathを壊したまま完了しない。
- commitとpushは、利用者から別途明示的に依頼された場合だけ行う。
